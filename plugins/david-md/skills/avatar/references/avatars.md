# Avatar lenses

Read only the entries relevant to the current decision. These are practical paraphrases of ideas associated with each thinker, not simulated personalities.

## Richard Feynman — understanding

Turn abstractions into a mechanism the reader can see in their head.

Ask:

- What is actually happening?
- Can this be explained without jargon?
- What concrete example would disprove shallow understanding?
- Which part do we think we understand but cannot reconstruct?
- Can we derive it again from first principles?

Prefer “Albert has ₱1,000 and sends Kar ₱300; what changes?” over “The platform facilitates peer-to-peer value transfer.”

## Paul Graham — users and product direction

Cut through startup theater and return to users.

Ask:

- Who wants this badly?
- What are they doing today instead?
- What is the smallest useful version?
- Is the problem observed or imagined?
- Can a surprisingly manual test answer the question?
- What happens if we do the obvious thing?

## John Gall — systems and MVP scope

Let a working simple system earn its complexity through observed pressure.

Ask:

- What is the smallest system that works end to end?
- Which complexity does reality require today?
- Which complexity anticipates an unproven future?
- What can a human do manually for now?
- What should wait until the simple system breaks?

## Don Norman — interaction design

Judge the interface through the user's mental model rather than the implementation.

Ask:

- What does the user think this does?
- What action appears possible?
- What do they expect next?
- After acting, can they tell what happened?
- Is the interface exposing an internal concept the user should not need?

Describe the experience from the user's point of view.

## Fred Brooks — conceptual integrity

Protect a small, coherent set of product concepts.

Ask:

- What few concepts make up this product?
- Does each feature feel like part of that same system?
- Are two features introducing competing mental models?
- Can a concept be removed instead of another one added?
- Could one person explain the entire product coherently?

Prefer three powerful concepts over fifteen individually reasonable ones.

## Edsger Dijkstra — programming complexity

Treat limited human cognitive capacity as an architectural constraint.

Ask:

- Can an engineer hold the execution path in their head?
- Does this abstraction reduce complexity or merely relocate it?
- Is cleverness hiding behavior?
- Can the code make state and control flow obvious?
- Are there unnecessary states?
- Would boring code be easier to prove correct?

## George Orwell — precise product writing

Attack language that lets a team sound aligned without agreeing on behavior.

Interrogate words such as “enable,” “leverage,” “seamless,” “flexible,” “robust,” “intelligent,” and “scalable.” Replace them with observable examples.

Prefer “Pizza orders try Grab first; if Grab fails, try Lalamove” over “The system supports flexible courier routing.” If an example cannot be produced, the requirement is not understood.

## Edward Tufte — information design

Show the important information directly and remove chrome that competes with it.

Ask:

- Can the product show the thing instead of describing it?
- What information earns screen space?
- What is decoration rather than information?
- Can one good visual replace several paragraphs?
- Would underlying records be more useful than an aggregate?

Prefer showing the three blocked projects and why over a card saying “3 projects need attention.”

## Richard Hamming — strategic attention

Choose important problems that have become attackable.

Ask:

- What are the important problems here?
- Which important problem can we plausibly attack now?
- Why is this worth time today?
- If it succeeds, does it materially matter?
- Are we polishing an unimportant problem because it is easy?

Avoid both tiny solvable trivia and grand but unattackable ambition. Seek importance multiplied by tractability.
