# Diagrams

Draw how something fits together as a published canvas: cards for things, lines for how they
relate, quiet regions for groups. Every card has one calm anatomy (icon, short name, subline,
optional pill, one sentence, facts). Colour only marks a pill or a kind of line. Things that are
off or only planned stay on the canvas, greyed or dashed, so the picture shows what is missing.

The page is fixed and designed; your job is the content: write the `MAP`, drop it into the page
below, show it. Never restyle cards or position anything by hand; Pele lays out every card and
line. For a decision (options, yes/no checks, a plan) use **decision-diagrams** instead.

## What this skill contains

Everything is in this file: the complete page, `diagram.html`, is at the end under **The page**.
It works in any project, with no repo, package manager or build step.

It loads **Pele** (`pele@1.7.0`, layout) from jsDelivr, required, and Inter and JetBrains Mono
from Google Fonts, optional. If jsDelivr is blocked the page says so; then `npm pack pele@1.7.0`,
put `package/dist/pele.global.js` next to the page and point the `<script src>` at it.

## 1. Plan the views

One canvas answers one question. Several questions ("what is stored", "who reads it") make
several **views**, shown as tabs (three at most). When the subject spans areas (people, files,
billing), list them as `domains` and tag cards with `domain`: the top bar gets a chip per domain
that shows only that domain's cards and what links to them, on every tab.

- **Structure** (tables, modules, teams): cards in **groups**, one per area; short labels on lines.
- **Flow between two sides** (who uses what): sources in one group, consumers in another; one line
  **kind** per way of connecting, shown in a legend.
- **Breakdown** (what each part holds): parent cards with child cards; one `warn` card for the gap.
- **Process** (steps, handoffs): `TB`, step cards in order, labels on branches.
- **Network** (agents, services, tools): `icon` nodes around one `hub: true`; kinds for call/answer.

Use `direction: 'LR'` for more than about eight cards: it stays readable on a wide screen.

## 2. Write the MAP

```js
const MAP = {
  kind: 'Kernel',                       // breadcrumb root: product, team or area
  title: 'How Kernel’s data fits together',
  meta: '',                             // one short provenance line, or ''
  stats: ['24 tables', '5 rooms'],      // optional; a leading number is set in bold
  kinds: {                              // line kinds; a view that uses them shows a legend
    ask: { label: 'Asks yes or no', tone: 'brand' },
    reads: { label: 'Reads the record', tone: 'ok' },
  },
  views: [{
    id: 'base', title: 'What base keeps', direction: 'LR',
    caption: 'Every record belongs to one Org. Grey names are the real tables.',
    groups: [{ id: 'people', label: 'People and Orgs' }, { id: 'files', label: 'Files' }],
    nodes: [
      { id: 'org', group: 'people', icon: 'building', title: 'Org', code: 'organization' },
      { id: 'file', group: 'files', icon: 'fileText', title: 'File', code: 'documents',
        line: 'Base keeps the bytes. Rooms get the name and size.' },
      { id: 'cust', group: 'files', icon: 'users', title: 'Customer file', state: 'planned',
        reason: 'Decided, not built yet' },
    ],
    edges: [{ source: 'org', target: 'file', label: 'owns' }],
  }],                                   // more views: more objects here, up to three
};
```

With a single view, put its fields (`direction`, `caption`, `groups`, `nodes`, `edges`) on the
map itself and leave out `views`.

Node fields:

| field | what goes in it |
| --- | --- |
| `id` | short, unique within the view, lowercase, no spaces |
| `shape` | `card` (default), `icon` (tile with the name under it: actors, tools), `note` (loose grey text) |
| `group` | a group id from the view's `groups` (a quiet region with a small caps heading) |
| `domain` | a domain id from `domains`, for the chips |
| `icon` | a name from the icon list |
| `title` | **one to three words** ("Room permissions", "Collections") |
| `sub` | the card's role or kind, a few words |
| `code` | a real identifier in mono (table, file, endpoint) |
| `badge` + `tone` | one short pill at the top right ("Most links", "Gap", "Busy"); colour from `tone` |
| `line` | one sentence, under about 90 characters |
| `facts` | one to three short facts joined by " · "; the first is the headline (a number) |
| `state` | `off` (greyed: unused, disconnected) or `planned` (dashed: not there yet) |
| `reason` | for `off` and `planned`: the footer says why ("Not linked to base yet") |
| `hub` | `icon` only: the centre of a network, larger with a soft ring |

Edge fields: `source`, `target`, `label` (two words at most), `kind` (a key of `kinds`),
`dashed` (maybe, planned, or a link to a note). Edges go in reading order, from the thing that
acts or holds to the thing it reaches. Avoid pairs of opposite edges between the same two cards;
use one edge and a kind or label that says both ways.

Tones: `plain`, `brand` (blue), `ok` (green), `warn` (orange), `violet`, `danger` (red), `faint`.
Use at most four line kinds in a view and give each its own tone. Keep `warn` and `danger` for
things that need attention.

## 3. Content rules

- Use the source's own names and numbers. Put the real identifier in `code`, the plain name in
  `title`.
- 6 to 25 cards per view. Fold small things into `line` or `facts` rather than new cards.
- Say the insight with the design, not with extra text: a `badge` on the card that matters,
  a `warn` card for a gap, `planned` for what is missing, `off` for what is unused.
- `caption` is the one or two sentences a reader needs before they start clicking.
- Use typographic apostrophes (’) and real minus signs (−) in visible text.
- If the subject is unclear, ask one short question first, then draw.

## 4. Build the page

Do not retype the page; copy it out of this file with a script and swap in your `MAP`.

1. Write your `MAP` (the whole `const MAP = { ... };` statement) to a file, say `map.js`.
2. Run this, with `SKILL` set to the path of this SKILL.md (the skill's base directory is shown
   when the skill loads), a page title of two to four words, and an output name:
   ```bash
   python3 - "$SKILL" map.js "Kernel Data Map" kernel-data-map.html <<'PY'
   import sys, re
   skill, mapfile, title, out = sys.argv[1:5]
   s = open(skill, encoding='utf-8').read()
   page = s[s.rindex('<!-- BEGIN diagram.html -->'):s.rindex('<!-- END diagram.html -->')]
   a = page.index('  const MAP = {'); b = page.index('  // ===== End of the map.')
   m = open(mapfile, encoding='utf-8').read().strip()
   page = page[:a] + '  ' + m.replace('\n', '\n  ') + '\n' + page[b:]
   page = re.sub(r'<title>.*?</title>', '<title>' + title.replace('&', '&amp;').replace('<', '&lt;') + '</title>', page, count=1)
   open(out, 'w', encoding='utf-8').write(page)
   print('wrote', out)
   PY
   ```
   With no shell, copy the page below by hand and replace only the block between
   `// ===== The map.` and `// ===== End of the map.`, plus the `<title>`.
3. Show it:
   - **Artifact tool available** (Claude Code, Claude projects): publish the one file with
     `icon: "map"` and a one-sentence `description`. To change it later, edit the file and
     publish the same path again so the link stays the same.
   - **claude.ai chat with HTML artifacts**: put the whole page in one HTML artifact.
   - **Local only**: save the file and open it in a browser. It works from `file://`; no server
     is needed.
4. Reply with the link and two or three lines: what each view shows and the one thing that
   stands out.

have a `reason`; the page `<title>` is a two-to-four-word name.
